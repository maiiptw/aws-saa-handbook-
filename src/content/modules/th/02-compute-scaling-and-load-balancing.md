# การประมวลผล, การขยายขนาด และการกระจายโหลด

การเลือกทรัพยากรประมวลผลที่เหมาะสม การปรับขนาดโดยอัตโนมัติตามความต้องการ และการกระจายการรับส่งข้อมูลอย่างมีประสิทธิภาพ เป็นสิ่งสำคัญมากสำหรับแอปพลิเคชันบน AWS ที่ต้องการความพร้อมใช้งานสูง (HA)

## Amazon EC2 (Elastic Compute Cloud)

EC2 ให้บริการความสามารถในการประมวลผลบนคลาวด์ที่ปลอดภัยและสามารถปรับขนาดได้

### รูปแบบการคิดราคา (Pricing Models)
1. **On-Demand**: จ่ายเท่าที่ใช้เป็นรายวินาที/ชั่วโมง เหมาะสำหรับงานระยะสั้น ข้อมูลพุ่งสูงเป็นพักๆ หรือเวิร์กโหลดที่คาดเดาไม่ได้
2. **Reserved Instances (RI)**: อัตราส่วนลดสำหรับการผูกมัดสัญญา 1 หรือ 3 ปี เหมาะสำหรับเวิร์กโหลดที่มีการใช้งานคงที่สม่ำเสมอ
3. **Savings Plans**: รูปแบบราคาที่ยืดหยุ่นซึ่งมอบส่วนลดแลกกับการตกลงการใช้งานในจำนวนที่คงที่ (วัดเป็นหน่วย $/ชั่วโมง)
4. **Spot Instances**: ส่วนลดสูงมากสำหรับทรัพยากรที่ว่างอยู่ เหมาะสำหรับเวิร์กโหลดที่ยืดหยุ่น ทนต่อความล้มเหลวได้ (เช่น การประมวลผลแบบแบตช์) AWS สามารถดึงทรัพยากรเหล่านี้กลับคืนได้โดยแจ้งเตือนล่วงหน้า 2 นาที
5. **Dedicated Hosts/Instances**: เซิร์ฟเวอร์ทางกายภาพที่จัดสรรให้คุณโดยเฉพาะ มักใช้ในกรณีที่มีข้อกำหนดด้านสิทธิ์การใช้งาน (Licensing) หรือข้อกำหนดทางกฎหมายที่เข้มงวด

## Auto Scaling Groups (ASG)

ASG ช่วยให้มั่นใจว่าคุณมีอินสแตนซ์ EC2 จำนวนที่เหมาะสมพร้อมรองรับโหลดของแอปพลิเคชัน
- **Launch Templates**: กำหนดการตั้งค่าของอินสแตนซ์ที่จะเปิดใช้งานโดย ASG (เช่น AMI, ประเภทอินสแตนซ์, Security Group ฯลฯ)
- **นโยบายการขยายขนาด (Scaling Policies)**:
  - *Target Tracking*: รักษาเมทริกซ์เฉพาะ (เช่น การใช้งาน CPU เฉลี่ย) ให้อยู่ในระดับเป้าหมายที่ตั้งไว้
  - *Step Scaling*: เพิ่มหรือลดความจุตามการแจ้งเตือน (Alarm breaches)
  - *Scheduled Scaling*: ปรับขนาดตามเวลาที่กำหนดล่วงหน้าได้ (เช่น เวลาทำการของธุรกิจ)

## Elastic Load Balancing (ELB)

ELB กระจายทราฟฟิกแอปพลิเคชันขาเข้าโดยอัตโนมัติไปยังเป้าหมายต่างๆ เช่น อินสแตนซ์ EC2, คอนเทนเนอร์ และ IP Addresses

### Application Load Balancer (ALB)
- ทำงานที่ **Layer 7** (Application layer)
- กระจายเส้นทางข้อมูลตามลักษณะ HTTP/HTTPS (เช่น Path, Host, Headers)
- รองรับ Path-based routing (เช่น ส่ง `/api` ไปที่ Target Group หนึ่ง ส่วน `/web` ไปอีกเป้าหมายหนึ่ง)
- เหมาะอย่างยิ่งสำหรับสถาปัตยกรรมไมโครเซอร์วิสและแอปพลิเคชันแบบคอนเทนเนอร์

### Network Load Balancer (NLB)
- ทำงานที่ **Layer 4** (Transport layer)
- กระจายเส้นทางข้อมูลตามโพรโทคอล IP (TCP, UDP)
- สามารถรองรับคำขอได้หลายล้านรายการต่อวินาทีด้วยความหน่วงในระดับต่ำมาก (Ultra-low latency)
- รองรับการให้ Static IP address สำหรับแต่ละ Availability Zone

### Gateway Load Balancer (GWLB)
- ใช้เพื่อปรับใช้ ขยาย และจัดการ Virtual appliances จากบุคคลที่สาม (เช่น ไฟร์วอลล์, ระบบตรวจจับ/ป้องกันการบุกรุก)
- ทำงานที่ Layer 3 (Network layer)

## จุดหลอกข้อสอบ (Exam Traps)
- **Spot Instances**: ห้ามใช้ Spot Instances สำหรับฐานข้อมูลที่สำคัญหรือเว็บเซิร์ฟเวอร์แบบ Stateful ที่ไม่มีระบบจัดการ State ภายนอกที่แข็งแกร่ง
- **ALB vs NLB**: หากคำถามระบุว่า "ความหน่วงต่ำสุดขีด (ultra-low latency)", "TCP/UDP", หรือ "Static IP" คำตอบที่ถูกต้องมักเป็น NLB แต่ถ้าระบุถึง "HTTP headers" หรือ "path-based routing" จะเป็น ALB
- **นโยบายเริ่มต้นเวลาลบ ASG (ASG Default Termination Policy)**: นโยบายเริ่มต้นจะทำการลบอินสแตนซ์ใน Availability Zone ที่มีจำนวนอินสแตนซ์มากที่สุด เพื่อรักษาสมดุลของระบบ
